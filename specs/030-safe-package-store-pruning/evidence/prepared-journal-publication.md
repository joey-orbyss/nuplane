# Native Prepared journal publication prerequisite

The internal execution context can publish one first-phase Prepared journal for an exact, freshly bound Eligible candidate. One context supplies one operation ID; individual candidates and publication stages have distinct IDs. A candidate can attempt publication only once in that context, including after an uncertain failure. Foreign, disposed and leaf-prepared candidates refuse before staging.

Publication recaptures the complete native manifest against the retained package-parent/basename/profile binding and requires exact baseline equality. It verifies root/control ancestry and profiles, enumerates the complete control namespace under the existing4,096-name cap, and reserves peak stage capacity within the separate1,024-artifact/64MiB prune limits. Malformed, aliased, unknown or conflicting evidence is preserved and refused. An unresolved pre-existing stage is not automatically replayed.

The publisher exclusively creates and flushes an exact stage, closes its file handles, reopens/verifies canonical spelling, native identity and strict journal bytes, then uses the existing native no-replace control-file publisher. A receipt is privately minted through the live context's actual publication path only after canonical readback and positive stage absence. It retains publication-time root/control identity and profile facts and expires with its candidate/context. It remains usable after candidate leaf closure by revalidating the retained parent binding. It describes publication and grants no package mutation authority.

If the native publication throws, inspect actual canonical/stage identities and bytes. Accept only a completely verified published state; an exact unpublished stage preserves the original failure, and ambiguous state preserves all artifacts and refuses. No blind native retry or prefix cleanup is permitted.
